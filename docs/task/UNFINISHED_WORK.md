### 首次部署网页配置（TODO-04）

用户明确要求：安装时需要的应用配置集中在首次登录后的页面填写，不再要求部署者手工编写 OSS 凭据文件或修改应用业务配置。已实现以下流程；完整 SQL 与操作步骤见[新部署指南](../NEW_INSTALL.md)。

1. **启动与初次登录**：全新环境即使没有 OSS/SMTP 也能打开初始化页面，不能用生产 Mock 绕过检查。`adminadmin` 仅用于首次受限登录；不能访问库、上传或其他正常业务。当前系统没有独立用户名登录字段，不擅自增加多用户/注册功能。
2. **强制改密**：先设置并确认新密码，不允许继续使用默认密码；后端执行状态校验，不能只靠页面跳转。改密后默认凭据和旧初始化会话失效，重启不恢复默认密码。
3. **OSS 页面配置**：填写 AccessKeyId、AccessKeySecret、Bucket、地域、媒体访问地址；对象前缀和公网/内网选项提供明确默认值或说明，Endpoint 根据已校验地域/网络生成，不再绑定当前用户的 Bucket、杭州地域及媒体域名。可选 ARN 应明确对应直接凭据或 AssumeRole 模式，不能填了却被静默忽略；不因此恢复旧私有视频播放流程。
4. **账号与邮件页面配置**：新账号默认纯密码登录；网页支持 QQ/163 SMTP 配置、主动发送测试邮件。完成初始化后可在系统设置开启/关闭邮箱登录验证，两种操作均需当前密码和真实收件验证码；不降低旧账号的 TOTP/邮箱要求。未配置邮件时仍可密码登录，不提供未配置邮件的假发送成功。
5. **保存、检查与启用**：显示配置校验和实际连通测试的独立结果；仅读取成功不等于上传权限已验证。实际发信、云测试和写入范围由用户明确触发，不自动改 Bucket/RAM 权限或删除测试对象。必要配置未完成时后端拒绝业务请求；失败可修改重试，重启可继续设置，完成后不重复进入向导。后续管理配置复用同一鉴权入口，不开放匿名修改。
6. **秘密与兼容保护**：AccessKeySecret、SMTP 授权码使用服务端独立主密钥加密保存；页面只返回脱敏信息/已配置状态，不回传已存秘密，不写入前端持久存储或日志。旧密码、邮箱/TOTP、数据、凭据文件和配置保持；已有账号、缺密钥或异常旧库不能回退成默认初始化。正式库迁移/配置导入须另行明确目标与授权。
7. **部署边界**：监听端口、数据挂载、HTTPS 证书/反向代理等打开页面所必需的基础设施由打包启动说明负责；主密钥由服务端安全生成和保存，不让用户在网页输入主密钥。可用的应用级配置再通过页面管理。

用户已确认：初始化后默认密码登录，邮箱配置/测试后才可选择开启验证；首次使用一次性安装码防止公开默认密码被抢先利用。完整新库 SQL 为 `docs/sql/NEW_INSTALL_FULL.sql`，当前合并最终 v8/41 表结构及正确账本；首次向导原为 v6/37 表，旧分散迁移与历史 SQL 保留，不要求新部署者逐份执行。
