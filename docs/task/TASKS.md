## 1. 默认协作规则

1. 开始前读取用户全局规则、`PRD.md`、本总看板、接口契约及自己的任务板。用户已授权媒体/前端，以及 CORE-02/03 和真实账号创建；不启动服务器部署，CORE-04～06 需另行启动。
2. 前后端统一 TypeScript；默认 A 方案。B 仅预留模块边界，本轮不实现直连播放或更改 OSS 公网授权。
3. 优先本地开发和调试。服务器已有 Docker、Redis、MySQL、Nginx；本轮不安装、配置或变更这些服务。
4. 三个子代理只写自己的负责目录和自己的任务板。需要修改其他负责人文件时，通过主控协调，禁止直接改其他代理的文件。
5. 同一个任务板只由对应代理回写。主控从三个任务板同步总览，三个子代理不得同时回写本文件。
6. `package-lock.json` 只由子代理 1 或主控串行更新。其他代理先提出依赖清单，不并发执行会修改共享锁文件的安装。
7. 子代理 1 维护根目录配置、共享类型、数据库 schema、迁移和后端注册入口。接口变更先同步契约再通知使用方，不让三个代理分别发明字段。
8. 不删除或覆盖用户文件，不擅自修改既有数据库或云端数据，不自动清理缓存、上传分片和日志。数据库写入、迁移运行和其他高风险操作遵守用户的确认规则；编写方案与脚本不等于授权执行。
9. 只记录实际改动和实际验证。不以 Mock 通过代替真实接口、安卓手机或 OSS 验收。
10. 任务开始实施才标记 `DOING`；完成并验证后标记 `DONE`。等待前置任务时保持 `TODO` 并注明依赖；真正无法推进时说明具体缺失信息。
11. 本地开发不能直连杭州 OSS 内网。默认通过 Mock/本地测试适配器验证；本机访问真实 OSS 公网必须明确配置和费用影响，不自动从内网回退公网。
12. 用户已授权将各功能模块加入 Git 暂存区；未授权提交/推送、切分支或历史操作，不丢弃任何用户改动。所有文档与源码使用 UTF-8 无 BOM。

## 4. 并行顺序与交接门槛

### G0：工程和接口准备

首先完成 CORE-01，确定工作区、构建命令、共享 DTO、鉴权接口、Repository 接口和媒体注册约定。接口契约已有初稿，CORE-01 将它落实为可编译的类型。

这段时间子代理 2 可准备存储适配器设计，子代理 3 可准备页面结构和 Mock 场景；不得抢改公共配置或擅自冻结另一套接口。

### G1：三个模块并行

- 子代理 1 继续数据库、账户与业务模块。
- 子代理 2 使用约定接口及 Fake Repository 开发媒体模块；实际仓库和鉴权实现交付后替换对接。
- 子代理 3 使用契约一致的 Mock 完成页面，逐项切换真实 API。

依赖尚未交付的部分以接口隔离，不能为了“先能跑”绕过生产鉴权或返回伪造的真实 OSS 成功状态。

### G2：接入与真实接口联调

子代理 1 统一注册媒体模块，主控核查三方字段、错误码、Cookie、CSRF、上传状态、Range 和统计口径。Mock 验证与真实 API 验证分别记录。

### G3：本地交付

提供前后端启动命令、VS Code F5 配置和操作说明。按 PRD 验收安卓上传和播放，明确哪些项仍需要服务器内网或真实 OSS 验证。真实部署和 B 方案继续保留在后续任务中。
