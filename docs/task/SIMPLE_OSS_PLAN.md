## 1. 产品目标

建设一个本人登录使用的视频管理页面，维护分组、标签与 OSS 视频地址的关联。视频上传到 OSS 后设为公共读，浏览器使用固定媒体域名和对象路径直接播放。

- 媒体域名：`https://oss.meetdawn.top`。
- OSS 对象统一位于 `onlineVideo/` 下。
- 分组由 JSON 配置决定，有多少个就展示多少个，空分组也展示。
- 每个视频属于一个分组，可有多个标签。
- 保留登录、上传、视频列表、搜索、播放和基本信息编辑。
- 网站登录保护页面、元数据管理和上传；公共视频地址本身无需登录，持有地址的人可直接访问。

## 2. 唯一业务链路

```text
登录 → 选择分组和标签 → 上传文件
     → 后端使用已有 OSS 凭据上传，新增对象设为 public-read
     → 保存标题、分组、标签和 objectKey
     → 返回 https://oss.meetdawn.top/{objectKey}
     → 页面原生 video 直接播放
```

上传经过后端，长期密钥仅由后端从已有受保护文件读取，不下发给浏览器。后端直接使用已有凭据初始化 OSS SDK，新链路不要求 STS/AssumeRole、角色 ARN 或临时播放签名。实际改造时核对该凭据的上传及新增对象公共读权限，权限不足应展示明确错误，不自动扩大 RAM 或 Bucket 权限。

上传 Endpoint 与媒体域名保持独立：本地上传使用现有公网 Endpoint，服务器部署时按实际环境使用内网 Endpoint；浏览器始终访问上述 HTTPS 媒体域名。

## 3. JSON 分组配置

计划新增 `config/library.json`，示例结构如下，示例分组不代表用户实际分组：

```json
{
  "mediaBaseUrl": "https://oss.meetdawn.top",
  "objectPrefix": "onlineVideo/",
  "groups": [
    { "id": "life", "name": "生活", "tags": ["家庭", "旅行"] },
    { "id": "study", "name": "学习", "tags": ["课程", "笔记"] }
  ]
}
```

规则：

1. `id` 是稳定分组标识和路径段，仅允许小写字母、数字及连字符；必须唯一。
2. `name` 是展示名称，可以修改，不改变已有视频路径；数组顺序就是页面展示顺序。
3. `tags` 是该分组的可选标签，上传或编辑时可多选。标签允许为空，不再开发独立标签管理页。
4. 首版在后端启动时读取配置，修改后重启后端并刷新页面生效，不增加配置监听或同步服务。
5. 分组改名、标签配置调整不自动修改历史视频数据或 OSS 对象。停用分组可用 `enabled: false`，禁止新上传，历史视频仍可在“全部视频”访问。
6. 配置只包含公开业务信息，密钥继续使用现有服务端秘密文件。

## 4. 对象路径和地址

新上传对象路径：

```text
onlineVideo/{groupId}/{UUID}.{原文件扩展名}
onlineVideo/life/3e125cc8-25ce-45bd-9ddb-11c807048d56.mp4
```

对应播放地址：

```text
https://oss.meetdawn.top/onlineVideo/life/3e125cc8-25ce-45bd-9ddb-11c807048d56.mp4
```

- 路径由后端依据有效分组生成，浏览器不提交任意对象路径。
- 保留合法文件扩展名及匹配的 Content-Type，使用唯一文件名避免覆盖。
- 分组目录是 OSS 对象前缀，无需单独创建目录。
- 数据库存 `objectKey`，API 根据配置计算并返回 `publicUrl`；不保存签名地址或到期时间。
- 文件名、分组名称等展示信息不用于拼接任意路径；旧对象路径保持原值。
- 仅新上传对象按本规划设为公共读；旧对象、整个 Bucket 的 ACL/Policy 不自动调整。

## 5. 最小业务数据与页面

视频记录对外只需要：`id`、`title`、`groupId`、`tags`、`objectKey`、`publicUrl`、`fileName`、`sizeBytes`、`createdAt`。时长和分辨率可以为空，不影响上传完成或发起播放。

继续使用现有 SQLite 和账号，不为简化重建数据库。实现时优先复用已有视频记录和标签关联，仅按必要程度补字段或映射。旧表、旧记录和上传历史保留，迁移方案须先检查现有数据并形成可审阅差异。

| 页面 | 首版功能 |
| --- | --- |
| 登录 | 沿用现有登录方式与退出功能 |
| 视频库 | 全部视频、配置分组、标题或标签搜索、标签筛选、分页、上传入口 |
| 上传 | 单文件、标题、分组、可选标签、上传进度和清楚的失败提示；成功后可立即播放或打开地址 |
| 视频详情 | 原生播放器、复制/打开公共地址、修改标题与标签；保留已有观看位置能力但不与播放授权绑定 |

上传分组在创建任务时确定。首版不增加自动移动云文件的跨组调整操作。现有地址登记时可以指定展示分组，保持旧文件位置。

播放使用原生 `<video controls>`。不再先创建播放会话，不发播放心跳、不续签、不经过视频代理。上传成功由 OSS 完成和数据库登记决定，FFprobe 检查不再作为播放入口的强制门槛。浏览器实际不支持编码时显示错误和“打开原地址”入口；公共读不改变视频编码，不承诺所有浏览器播放所有格式。

上传传输尽量复用现有流式/分片能力与既定文件大小上限，先解耦组织快照、私有授权和强制内容分析等额外要求。页面不要求用户操作上传 ID 或理解完成状态机；不在本轮另建上传框架。

已有公开视频可用同域名、`onlineVideo/` 范围内的地址手动登记，再关联分组和标签。登记不搬动、复制或重新上传视频，不递归扫描整个 Bucket。

## 10. 本地账号工具（2026-10-03）

新增 `apps/api/scripts/account-tool.ts`，可独立执行，无需 API、Web 或 OSS。`account-setup.json` 中的初始 `password` 和 Base32 `totpSecret` 为明文资料，不需要解密；数据库中的密码是 Argon2id 单向哈希，TOTP 密钥为 AES-256-GCM 密文。工具直接复用现有算法，不重写加密实现、不初始化账号、不写正式库、不消费验证码。

```powershell
node --import tsx apps/api/scripts/account-tool.ts show
node --import tsx apps/api/scripts/account-tool.ts code
node --import tsx apps/api/scripts/account-tool.ts --help
```

`show` 仅在本机终端显示原密码和当前验证码，先校验初始密码是否仍匹配当前账号；`code` 只显示验证码与有效时间，使用数据库中当前 TOTP 密钥而非可能过时的初始绑定资料。密码与验证码不写报告。已消费的周期会明确提示等待新码。

工具还支持 `hash-password/verify-password/encrypt-secret/decrypt-secret --input <.local内JSON文件>`，加解密默认使用原 `.local/secrets/auth.key`，可显式指定 `--key-file`。随机盐与随机 IV 会导致相同输入的哈希/密文不同，通过校验或解密验证一致性。

验证：新增 4 项隔离测试及 API 类型检查通过；实际本地账号只读验证可读取密码和生成六位验证码，前后账号记录一致。前端交接与实云验收仍维持上一节暂停状态。

用户新增范围：开发真实封面；一次选择多个视频；在封面预览下方增加待上传视频列表，点击条目切换封面和信息；主导航增加“任务列表”，集中承载上传执行、进度、暂停、恢复及失败处理。本节仅形成规划，不修改业务源码、正式数据库或 OSS。新增封面需求覆盖原“暂缓自动封面”约定，其他暂缓事项保持。

### 11.1 当前代码依据与页面职责

| 位置 | 调整后职责 |

| 上传视频页 | 多选/追加视频、点击待上传条目、查看当前封面、编辑当前视频标题/分类/标签、提交队列 |
| 封面预览下方 | 本次待上传列表，显示缩略图、文件名/标题、大小、准备状态和选中状态；点击切换当前条目 |

### 11.2 封面来源与失败处理

建议优先级：**可识别的视频内嵌封面 → 开头约 1 秒的有效画面 → 暂无封面占位**。已有本网站封面优先复用；不根据同目录文件名猜测“配套封面”，不把外部网站的封面当作视频文件内嵌图片。

1. 网页当前没有内嵌图片解析能力。内嵌封面需要新增有边界的容器解析，先用真实带封面样例核定支持范围，优先常用 MP4/MOV；其他容器或损坏元数据不能宣称全格式支持，识别失败回退截帧。
2. 浏览器通过本地 File/Blob URL 解码和截帧，不上传整个文件来做预览，不对整个大视频调用 `arrayBuffer()`。默认选约 1 秒，短视频取时长中间附近，避免直接以第 0 帧作为默认；无法取得有效帧时显示“暂无封面”。预览标识来源“视频自带封面”或“视频截帧”。
3. 首版不增加手动选帧、自定义图片上传或三张候选封面流程。封面区展示当前选中视频的一张真实图片，列表点击切换的是视频，不混淆为选择候选帧。
4. 内嵌图片需重新解码为统一静态图片，建议 JPEG、最长边 960 像素、单张不超过 1 MiB；限制提取时间与并发，先逐个处理。切换条目不串图，移出待选条目或退出页面时释放对应 Blob URL。
5. 浏览器无法解码时，封面失败不阻止创建视频任务、上传或后续直接播放。可选后端 FFmpeg 静态图片兜底作为独立补封面任务；工具不可用也不成为上传门槛。已有本地 FFmpeg 文件不等同生产已配置可用，需单独检查。
6. 首版仅为新提交视频采集封面，不自动扫描或回填全部旧视频。已有公网地址登记如没有本地文件先使用占位，不为了封面下载全部旧对象。

持久化建议：视频登记完成后，将本地生成的图片通过受登录和 CSRF 保护的后端接口上传；后端复用服务端 OSS 凭据与存储适配器，新图片对象设 public-read，生成 `onlineVideo/{categoryId}/covers/{UUID}.jpg`。数据库只保存封面 objectKey，API 根据固定媒体域名生成 `coverUrl`。复用 `thumbnail_key`、`thumbnail` 资产角色及既有存储记录，保留旧 `thumbnailUrl` 契约；公共页面用 `coverUrl`，不重新接入旧视频代理或签名授权。

视频上传完成与封面保存分开确认：视频成功但图片失败时，任务显示“视频已上传，封面待补”，提供补封面重试；不重传视频、不虚报封面成功。图片对象完成但关联保存失败也需保留可恢复记录，重试只完成关联。旧封面与旧云对象不自动删除或覆盖。

### 11.3 多文件选择与待上传列表

1. 文件选择增加 `multiple`，拖放多个文件走同一入口；再次选择为追加，不替换本次待上传列表。
2. 每个条目分配稳定的本地 `clientId`，分别持有 File、封面、标题、分类、标签及校验结果，不以数组下标、文件名或标题作为任务关联键。同名但大小或修改时间不同的文件可共存。
3. 默认选中第一条，右侧表单显示该条目的信息。标题默认取不含扩展名的文件名；分类使用配置中的有效默认分类，标签默认空。切换条目先保留当前编辑；修改一个视频不影响其他条目。首版提供“将当前分类和标签应用到全部待提交视频”，明确触发后才批量应用，不覆盖各自标题；切换分类清空该条目不适用的标签。
4. 每个文件独立校验非空、合法视频扩展名与现有单文件大小上限，非法条目标明原因，不让一个超限文件阻断其他合法文件。封面提取与上传准备独立。
5. 未提交条目可“移出待选列表”，仅解除本次浏览器选择，不删除本地文件。已经提交的条目展示对应任务入口，避免再次点击产生新任务；不在首版增加云端删除或清空任务历史操作。
6. 上传页仅保留文件准备及提交入口，按钮建议为“提交 N 个视频并上传”。提交后进入任务列表，逐个创建独立服务端任务并排队上传；若部分任务创建失败，成功部分保留，失败条目可单独重试。

### 11.4 任务列表与跨页面执行

主导航增加“任务列表”，桌面与移动端均提供入口。上传页现有进度、暂停、续传、完成确认重试、已完成结果和恢复已有任务模块转到此页；旧代码/记录保留，日常界面不要求用户手动输入任务 ID。

- 任务卡片显示封面（未保存时占位）、标题、文件名、大小、分类/标签、字节进度、状态、错误原因和操作；支持全部/进行中/已完成/失败筛选及分页。旧任务也从服务端读取，不能仅依赖当前浏览器 localStorage 提示。
- 每个视频一个独立任务。首版每次传一个视频，继续复用现有分片及服务器并发上限；多个视频排队处理。一条失败后保留错误并继续其他条目；重试用原 uploadId、原 objectKey 和已确认分片，不重新创建对象。
- 上传执行器放在登录后的应用级共享状态/服务中，由上传页和任务页共用；切换到视频库、详情或任务列表不再因 `UploadPage` 卸载而中止上传。退出登录时停止本机执行，不自动删除任务、已完成对象或分片。
- 服务端已有 `uploading/finalizing/completed/failed` 结果为依据；排队和暂停属于本机执行状态。“已传完所有字节”不等同“视频登记完成”，“视频登记完成”也不等同“封面已保存”。封面状态单独表达。
- 完成项提供播放、打开与复制公共地址。视频完成、封面失败时仍可播放，并可单独补封面。
- 页面刷新或浏览器重启后，任务进度和结果从数据库恢复；浏览器不能自动找回用户之前选中的本地视频 File。未完成任务显示“重新选择原文件继续”，按原大小及已完成分片 SHA-256 验证后续传。只保存必要的本地队列提示，不默认把整个大视频持久化到浏览器存储。

## 12. 配置管理增删改查与首页联动（已实施，最新删除规则见第 13 节）

用户新增第四项调整：在现有“配置管理”中完成分类与标签的增删改查。首页视频库“全部视频”旁的分类按钮由这里维护；新增后显示对应分类，删除后不再显示该分类。空分类仍显示，顺序与管理配置一致。不恢复分组功能。

### 12.1 当前缺口与统一来源

实际源码存在双来源：`GET /api/library` 和公共模式 `GET /api/categories` 读取 JSON，现有分类/标签新增及修改接口却写 SQLite。因此只提交旧新增接口不能证明首页联动成功。实施必须统一配置管理、首页、上传和登记表单的读写契约，保留 JSON 配置方案，不擅自把数据库独立维护的名称集合当作另一套正式配置。

`config/library.json` 继续作为分类与可选标签的业务配置。管理接口只修改用户明确提交的分类/标签字段，固定媒体域名、对象前缀及秘密文件不属于可编辑项。成功后安全更新运行时配置，页面使配置查询失效并刷新；本任务取代旧“配置修改需重启才能生效”的首版限制。重启后读取保存的配置，不回退到初始样例或丢失编辑。

需要先冻结 JSON 与既有分类/标签稳定 ID 的兼容方案，特别是标签改名如何保留 tagId 和旧视频关联。不得出现“界面显示新名称，但搜索或上传仍读取旧名字”“管理写 SQL、首页仍读旧 JSON”的情况。涉及 JSON 与 SQL 同步时，先明确失败恢复机制，任一持久化失败不能虚报成功。

### 12.2 功能与历史数据规则

- 分类：列表/名称查询、新增、改名、排序、业务删除。ID 由服务端生成且稳定；改名不改变 categoryId、原视频 objectKey 或 OSS 目录。已有默认“未分类”保留兼容，不擅自删除。
- 首页：始终保留“全部视频”；活动分类按管理顺序显示，包含空分类。新增、改名、排序后更新对应按钮；删除后移出活动按钮和新上传可选项。若当前筛选指向刚删除分类，清除该筛选并回到“全部视频”。
- 分类删除建议采用可恢复的软删除/停用：界面确认具体分类和影响后隐藏活动入口、禁止新任务选择；保留配置历史、SQL 分类、视频关联、上传记录及云对象。相关视频仍可在“全部视频”和搜索结果找到，详情保留历史分类名称或已停用标识；不自动改为未分类、不搬动云文件。
- 标签：在所属分类允许的标签范围中查询、新增、改名和移出可选范围。稳定 tagId 与历史关联保留；移出后新视频不可选，旧视频已有标签仍展示和可搜索。其他分类共用同一标签时，必须明确重命名或删除的影响范围，不能静默改掉其他分类的配置。
- 既有公共上传任务按创建时已校验的分类/标签与对象路径继续恢复；之后的停用或改名不应让已上传的文件/分片丢失，也不能在重试时重新创建新对象。新任务按最新活动配置校验。
- 管理请求仍需真实登录、CSRF、本人归属校验、名称规范化与重复检测。明确未登录、配置只读、版本冲突、保存失败等错误。

### 12.3 保存与验证

配置管理写入须校验完整结果，使用更新锁与版本冲突检测防止并发丢失；原配置生成唯一备份，临时文件写入完整后再原子更新。失败时保留可用旧版本、原账号、旧关联及临时/备份文件，不自动清理。正常 CRUD 写入只更新已提交的管理配置，不覆盖 `.env`、账号资料、密钥或其他用户配置。

验收包括：新增空分类立即出现在“全部视频”旁；改名只更新名称；排序立即生效；新分类可上传并可添加其标签；标签增改查影响正确；删除分类后按钮消失而旧视频仍可查询播放；删除标签不删旧视频关联；刷新和后端重启后配置保留；并发编辑/写盘失败不会静默丢失修改。测试完成后才进行授权范围内的真实业务验证，不把 Mock 结果标为已完成。

### 12.4 与第 11 节的并行划分

实施可由一个主线程协调三个子代理：

1. 配置/数据/公共契约代理：分类标签 CRUD、JSON 保存与运行时刷新、首页联动契约、任务/封面 DTO、Repository、必要增量 SQL 和兼容测试。独占 shared/core/db/catalog/progress 及后端入口；根 package/lock 仅主线程指定后串行维护。
2. 媒体代理：分片任务列表及恢复、幂等创建、图片保存与封面恢复、公共 OSS 路径与权限测试。独占 media 及媒体测试；需要 Repository/schema/共享契约时由代理 1 配合，不能越界写入。
3. 前端代理：保留样式成果，接入多文件与封面预览、应用级执行器、任务页面、配置 CRUD、首页按钮刷新及浏览器验证准备。独占必要 web/src 和前端测试；先确认其他模型已交接，不能同文件并发编辑。

主线程先核对当前代码与未提交差异、协调写入归属，再冻结公共契约。依赖契约的部分冻结后才能接入；前端内部多个任务分阶段进行，不另派代理并发写同一页面。主线程独立检查实际代码、测试、构建和真页面，完成记录继续集中写回本文。本次仅新增规划与执行提示词，没有启动新代理、实施 CRUD 或扩大云端操作范围。

## 13. 第 11、12 节实施与独立验收（2026-10-03）

本节记录实际实施，覆盖第 11、12 节中的“尚未实施”历史描述。用户已确认其他模型停止前端写入，本轮三个子代理按指定目录独占写入；主线程独占包依赖、集成脚本及本文，独立读代码、验证与交付。没有切换分支、提交、推送、丢弃既有修改或删除文件、产物、账号、数据库记录、云对象。

### 13.1 实际功能和冻结契约

- 真实封面：`cover.ts` 按 MP4/MOV box 偏移读取并跳过 `mdat`，首版识别 iTunes `covr` JPEG/PNG；统一重编码 JPEG、最长边 960、单张 ≤1 MiB。不能识别时用本地 Blob URL 截约 1 秒，有限时长 ≤2 秒取中间；WebM 的 Infinity 时长尝试 1 秒，仍受超时控制。逐个采集，总超时 14 秒，释放 Blob URL，不整读大视频。后端 JPEG 实际解码校验使用 `jpeg-js@0.4.4`；封面失败不阻断视频上传或播放。
- 封面保存：`PUT /api/videos/:videoId/cover`，后端现有 OSS 凭据写新唯一 `onlineVideo/{categoryId}/covers/{UUID}.jpg`，新图片 `public-read`、禁止覆盖。复用 `thumbnail_key`、`video_assets.thumbnail`、存储对象/操作表，API 生成 `coverObjectKey/coverUrl/coverStatus`。图片成功但关联失败复用原 key，重试核验真实图片 SHA-256 后仅关联，旧封面对象保留。库显示图片，原生播放器使用 poster；不扫描旧视频。
- 多文件：选择及拖放多个视频，再选追加；每项随机稳定 `clientId`、独立文件校验/封面/标题/分类/标签。点击待上传项切换信息；明确批量应用分类标签且不改标题；移出只解除浏览器选择。部分任务创建失败在任务页使用原 `clientRequestId` 重试，成功项不重复创建。
- 任务：`GET /api/uploads` 本人分页及状态筛选；应用级 `UploadQueue` 串行执行，切换路由不中止，退出登录停止本机执行。服务端字节上传、视频登记、封面保存分开显示。刷新读取真实历史，补选 File 后验证大小及全部已确认分片 SHA-256，保留 uploadId/objectKey/分片。零已确认分片没有原摘要可比，界面明确说明，未宣称全文件 SHA-256 已匹配。桌面及移动导航都有任务入口。云初始化、实际传片或校验失败持久记录安全错误码，失败历史包含这些未完成任务；原状态允许续传，保存合法分片后原子清错。用户暂停/请求取消不算失败，完成视频的封面失败独立展示。
- 配置：`GET/PUT /api/library/configuration` 只开放分类、标签和版本，不开放媒体域名/对象前缀/密钥。JSON 是活动配置来源，旧字符串 tags 兼容，新增 `tagDefinitions/tagIds` 保持稳定 ID。JSON/SQLite 使用持久 pending 日志、更新锁、完整验证、唯一备份、临时文件 fsync/原子替换、SQL 与 committed 同事务；失败补偿旧文件，无法安全恢复则明确拒绝服务。保存更新共享运行时对象，前端刷新数据，重启仍保留。`BroadcastChannel` 与 `storage` 仅发送随机 revision，其他同源标签页通过鉴权重新读配置，删除当前筛选分类会自动回到全部视频。
- **最新删除规则以用户补充为准**：默认保留“未分类”。删除分类展示视频/任务数量的确认弹窗，确认后业务软停用分类，该分类视频归默认“未分类”；原视频 objectKey、OSS 路径、封面和稳定标签关联保持。取消不写入；恢复分类不自动搬回。未完成任务保留创建快照续传，登记时原分类已停用则视频归“未分类”，不新建对象。标签改名影响全部共用分类/历史关联，停用标签不删除旧关联。
- 反馈：活动公共页面操作反馈统一主题浮动 Toast，成功/信息约 3.5 秒、错误约 6 秒，支持关闭与悬停/焦点暂停；确认弹窗等待明确选择，支持取消默认焦点、Tab 圈定、Escape 取消及焦点返回。持久任务状态和恢复错误仍在任务卡片中展示。沿用原 React、科技主题与 className；只补必要局部 CSS，没有引入 Vue、Tailwind 或重做界面。
