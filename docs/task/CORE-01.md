三、CORE-01 实现范围

1. 工程骨架

建立 npm workspaces，规划：
- apps/api：Fastify + TypeScript 后端。
- apps/web：后续由前端代理创建。
- packages/shared：前后端可共享的数据类型。

建立必要的 package.json、TypeScript 配置、构建和开发脚本。
前端尚未创建时，后端与共享包仍能独立安装、检查和构建。
不要为了让工作区成立而开发前端页面或覆盖前端文件。

依赖版本应核验兼容性并锁定，适配受支持的 Node.js 版本。
安装依赖和更新 package-lock.json 串行执行。

2. 后端基础

提供可启动的 Fastify 应用和启动入口。
区分应用构建与端口监听，便于后续测试和模块注册。

实现 GET /api/health：
- 返回简单健康状态。
- 不返回凭证、数据库路径、OSS 配置或其他敏感信息。
- 本任务的健康检查不依赖真实数据库或 OSS。

配置统一错误响应、必要日志和配置读取基础。
配置错误应明确报错，不能悄悄切换真实服务或降低安全要求。

3. 公共数据契约

依据 docs/API_CONTRACT.md，落实可编译的：
- DTO 和请求/响应类型。
- 视频及上传状态。
- 分页结构。
- 错误码和错误响应结构。
- A 方案播放模式类型。

明确可空字段、时间格式和字节单位。
明确 limitBytes 为 null 时的含义，不能把缺失配置默认解释为无限授权。

packages/shared 只放前端可安全引用的结构。
Node.js 流、服务端鉴权及内部存储接口放在后端公共契约目录，
避免前端依赖 Node.js 或服务端实现。

4. 后端模块协作接口

定义并记录：
- AuthGuard
- VideoRepository
- UploadRepository
- PlaybackRepository
- UsageRepository
- StorageAdapter 的协作边界
- MediaModule 的注册函数及依赖注入结构

这些接口应让媒体代理可以先使用 Fake/Mock 独立开发。

本任务只建立类型、接入约定和必要测试替身：
- 不实现真实 SQLite Repository。
- 不实现完整登录、TOTP 或业务模块。
- 不实现 OSS 适配器、上传或视频流。
- 不提供生产环境默认放行的鉴权实现。
- 生产接入缺少必要安全依赖时应安全失败。

统一分片 checksum 的算法、编码格式、传递方式及校验责任。
计算应按分片进行，不能要求把完整大视频加载到内存。
将最终约定同步到 docs/API_CONTRACT.md。
