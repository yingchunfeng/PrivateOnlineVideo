版本：V1.0  
编写日期：2026-09-30

## 1. 产品目标与已确认决策

建设一个适配安卓手机的视频网站，将手机视频上传到阿里云 OSS，通过分类、封面和搜索随时找到视频并在线播放，无需先将完整文件保存到手机。

产品仅供本人使用，优先保证视频隐私、访问安全和流量可控。开发阶段默认采用 A 方案；后续确认服务器带宽不足时，再评估并明确启用 B 方案，不自动切换。

| 项目 | 决策 |
| --- | --- |
| 使用设备 | 安卓手机，兼顾电脑浏览器 |
| 使用范围 | 本人使用，不面向公众开放视频 |
| 产品形态 | 手机优先的响应式网站；原生 App 不属于当前开发范围 |
| 核心功能 | 分类查看、搜索、在线播放、手机上传 |
| 存储服务 | 已确定使用阿里云 OSS |
| 当前播放链路 | A：后端鉴权后转发 OSS 视频 |
| 后续备选链路 | B：后端授权，手机直接从私有 OSS 播放 |
| 部署方式 | Docker Compose 容器化部署到现有轻量应用服务器 |
| 数据保护 | 保留原视频；不默认覆盖原文件或执行永久删除 |

PWA 添加到桌面可作为后续增强，不作为第一阶段上线前提。A、B 指视频传输方式，与网站或 App 的产品形态无关。

### 2.2 网络与费用边界

- 杭州轻量服务器可通过同地域 OSS 内网 Endpoint 访问资源：`https://oss-cn-hangzhou-internal.aliyuncs.com`。
- A 方案通过内网读取 OSS，不产生 OSS 内网流出流量费；存储和请求仍按相应规则计费，服务器出网按现有套餐规则处理。
- 3Mbps 理论传输速度约为 375KB/s，实际可用速度还受协议开销和网络波动影响。
- 原视频码率高于可用带宽时，A 方案可能缓冲，不能承诺所有手机原片都流畅播放。视频分辨率不能单独用于判断带宽需求。
- 网站布局适配不会自动压缩视频。转发原文件不改变编码、分辨率或画质。
- B 方案的视频流量直接从 OSS 传到手机，不占用服务器视频出网带宽，但会产生 OSS 外网流出流量费用。
- 40GB 存储包用于抵扣符合条件的存储用量，不代表包含 40GB 观看流量。重复观看会累加实际传输量。
- 云端监控、账单及资源包告警可能存在延迟，告警不是费用封顶机制。

## 3. 目标用户与主要流程

### 3.1 唯一用户

系统只有本人账户，不开放公众注册、访客观看或视频分享。上传、查看、分类管理和安全设置均需要本人登录。

### 3.2 浏览与播放

1. 用户打开网站并完成登录。
2. 查看分类与视频封面，按分类或标题筛选。
3. 点击视频进入详情页，显示标题、时长、分类和可用播放版本。
4. 后端检查会话、播放权限、并发和流量限额。
5. A 方案由后端通过 OSS 内网读取视频，按浏览器请求流式返回。
6. 用户可暂停、拖动进度、全屏，离开后保存观看位置。

在线播放仍会传输并缓存必要的视频数据，但不要求先完整下载再观看。当前不提供完整文件下载入口，也不承诺阻止已获授权用户录屏或保存数据。

### 3.3 手机上传

1. 用户选择手机中的视频，填写标题并选择分类。
2. 后端创建与当前账户绑定的上传任务，并生成唯一对象路径。
3. 手机分片上传到后端，后端分片写入 OSS，前端显示进度。
4. 网络中断时保存上传状态；恢复时继续上传未完成部分。
5. 完成后由后端校验对象和必要元数据，再将视频登记到视频库。
6. 视频兼容时进入可播放状态；不兼容或处理失败时显示明确状态与处理方式。

网页上传可能在安卓锁屏、切换后台或浏览器回收页面时中断。界面应提示保持前台；页面重新打开后，允许重新选择同一文件并校验后续传，不能承诺后台持续上传。

## 5. 播放链路设计

### 5.1 A 方案：第一阶段默认

```text
安卓浏览器
  → 网站统一入口
  → 后端登录、权限、并发和流量检查
  → 杭州 OSS 内网 Endpoint
  → 后端流式转发视频给浏览器
```

要求：

- 浏览器获得站内播放地址，不获得可直接访问 OSS 的视频签名 URL。
- 播放地址每次访问均检查会话，不以知道地址作为授权条件。
- 无权限或超限请求在读取视频数据前拒绝。
- 正确处理 `HEAD`、合法 `Range`、`206 Partial Content`、`Content-Range`、`Accept-Ranges` 和错误范围响应。
- 设置正确的视频 `Content-Type`，避免播放器触发附件下载行为。
- 不以全量下载到内存或磁盘的方式实现播放、预加载或拖动进度。
- 客户端断开时及时取消对应的 OSS 数据读取。
- 以播放会话管理并发；一个播放器可能发起多个 Range 请求，不能简单将每个 HTTP 请求视为一个观看设备。
- 流量限额按实际转发字节累计；并发请求、重试、拖动进度和重复播放都纳入统计。
- 达到限额时限制新请求，并终止正在超限传输的请求；统计误差与终止延迟应有明确边界。

### 5.2 B 方案：后续按需启用

```text
安卓浏览器 → 后端登录与播放授权 → 获得短期播放地址
安卓浏览器 → OSS 外网访问 → 视频数据直接进入播放器
```

要求：

- OSS 保持私有访问，由服务端生成仅针对指定对象、指定操作的短期授权。
- 不向浏览器暴露长期 AccessKey，不生成长期公开播放地址。
- 评估来源 IP 限制；需要验证 OSS 实际看到的公网 IP、IPv4/IPv6 和手机切网行为。
- 根据视频格式和访问行为配置播放域名、HTTPS、响应头和必要的 CORS；中国内地 OSS 绑定自定义域名需完成相应备案。
- B 方案可限制授权发放，但后端无法直接计量或立即截断所有 OSS 直连传输。
- 短期链接仍可能在有效期内被复用；单连接限速不能当作总流量或总费用上限。
- 启用 OSS 流量、请求和费用监控，明确监控延迟与异常处理流程。

### 5.3 A 切换 B 的条件和步骤

切换条件：实际样例在 A 下持续缓冲，且确认主要原因是服务器出网带宽；用户选择承担 OSS 外网观看流量费用。

切换必须完成以下工作，不仅是修改一个环境变量：

1. 核实费用预期，确定授权有效期、监控及异常处理规则。
2. 检查 A 阶段的 OSS 网络限制；若只允许内网读取，公网签名 URL 也会被拒绝。提出具体授权调整方案，经用户确认后执行。
3. 配置并验证 B 所需的域名、HTTPS、跨域和播放响应头。
4. 测试链接泄露、授权过期、手机切网及播放续接。
5. 明确设置播放模式为 B；保留可回到 A 的实现与配置。

视频列表、分类、观看记录和 OSS 对象路径保持兼容，无需因播放链路变化重新上传视频。服务端不因播放失败或带宽不足自动降低网络限制、公开 Bucket 或切换为 B。

如使用私有网络访问网站，B 方案应明确分流规则：网站管理请求走私有连接，OSS 视频走手机公网。如果视频仍绕行服务器上的全隧道连接，仍会受到服务器 3Mbps 出网限制。

## 6. 安全与防刷要求

### 6.1 OSS 与凭证

- Bucket 与视频 Object 均检查私有访问状态，并核查现有公共授权；不能只修改 Bucket ACL 后就认为所有对象已私有。
- 应用使用最小权限身份，限定指定 Bucket 和应用对象前缀；不使用主账号密钥。
- A 阶段优先限制视频读取的网络来源，并结合应用身份授权。轻量服务器 VPC 由阿里云分配，策略需实测，预留安全的管理路径。
- 凭证仅服务端运行时读取，采用只读 secret 文件或等效方式，不进入镜像、前端构建产物或版本库。
- 日志不得记录密码、验证码密钥、完整会话凭证或完整签名播放 URL。
- OSS 授权调整可能影响本人和其他业务，部署时先检查现状，再实施经过确认的具体方案。

### 6.2 网站与会话

- 正式使用 HTTPS；公开访问和私有网络访问分别配置适当的入口限制。
- 密码采用可靠的密码哈希算法，不明文保存。
- 会话 Cookie 配置 `HttpOnly`、`Secure` 和适当的 `SameSite`；支持会话撤销和过期。
- 写操作实施 CSRF/来源检查；前端页面限制、CORS、Referer 不作为独立身份验证手段。
- 登录、上传、播放授权和视频数据接口分别设置适当的请求限制。
- 浏览器提交的视频 ID 必须由后端映射到受控对象，禁止任意 OSS 路径访问和路径穿越。
- 仅信任明确配置的反向代理提供的客户端 IP 信息，不直接相信任意客户端的转发头。

### 6.3 流量控制

| 控制项 | A 阶段要求 | B 阶段边界 |
| --- | --- | --- |
| 播放权限 | 每次视频请求检查会话 | 授权发放时检查，OSS 验证有效签名 |
| 请求频率 | 限制管理与播放请求 | 后端可限制授权接口，不能限制所有直连请求 |
| 播放并发 | 按会话/设备控制，并兼容播放器 Range 请求 | 后端会话数不等于 OSS 实际连接数 |
| 每日传输上限 | 按后端实际发送字节执行应用限额 | 依赖云侧监控及控制，有延迟，不能直接套用 A 的硬限额承诺 |
| 异常处置 | 拒绝请求、撤销会话、暂停播放 | 停止发放新授权并执行预先设计的云侧处置 |
| 费用上限 | 应用限额不等于所有云服务费用封顶 | 不承诺仅靠短期链接、告警实现费用封顶 |

不默认提供永久删除功能。隐藏视频条目不删除 OSS 原文件，也不释放存储空间。失败上传的分片、临时文件及日志不擅自清理；需要清理时说明范围并取得确认。

## 8. 技术方案与容器部署

以下为建议实施方案，不代表已经安装或配置。

### 8.1 技术栈

前后端统一使用 TypeScript。下表作为第一阶段的推荐技术基线，具体依赖版本在开发时核验兼容性并锁定，不直接使用浮动的最新版本。

| 部分 | 技术选择 | 用途与约束 |
| --- | --- | --- |
| 前端语言与框架 | TypeScript + React | 手机优先的响应式网站，开启严格类型检查 |
| 前端构建 | Vite | 本地开发和静态资源构建；生产部署构建产物 |
| 页面路由 | React Router | 登录、视频库、详情、上传与设置页面 |
| UI 与样式 | Tailwind CSS，按需使用 shadcn/ui | 统一组件样式，适配手机触控、横竖屏和基础无障碍操作 |
| 前后端通信 | HTTPS + REST API | 前后端同源部署，减少跨域与会话管理复杂度 |
| 后端运行时 | Node.js 受维护的 LTS 版本 | 承载接口、OSS 访问和视频流式转发 |
| 后端语言与框架 | TypeScript + Fastify | 路由、请求校验、鉴权、上传与播放接口 |
| 接口校验 | Fastify JSON Schema | 校验参数、请求体与返回结构，限制非法路径及异常输入 |
| 数据库 | SQLite | 单人单机元数据、会话、上传任务和流量记录，数据文件持久化 |
| 数据访问 | Drizzle ORM + better-sqlite3 | 类型安全的数据访问及数据库迁移；迁移不得静默丢弃数据 |
| 播放器 | HTML5 Video | 第一阶段播放兼容 MP4；实现暂停、拖动、全屏和进度恢复 |
| A 方案传输 | HTTP Range + Node.js Streams | 按需读取、背压控制、断开取消和实际传输字节统计 |
| OSS 接入 | 阿里云 Node.js SDK `ali-oss` | 服务端通过内网访问；采用支持的 V4 签名，不向浏览器暴露长期凭证 |
| 上传实现 | 浏览器 File API + 后端分片接口 + OSS Multipart Upload | A 阶段上传通过后端，保存任务和分片状态，支持续传 |
| 登录安全 | Argon2id + TOTP + 服务端会话 | 安全密码哈希、动态验证码、会话过期与撤销；会话持久化到 SQLite |
| 请求限流 | Fastify 限流插件 + 应用级传输限额 | 请求频率限制与播放字节限额分开实现 |
| 日志 | Fastify 内置 Pino | 记录必要的操作和异常信息，过滤凭证与敏感播放地址 |
| 视频信息分析 | FFprobe | 采集编码、时长和分辨率；按需运行并控制资源使用 |
| 统一入口 | Nginx | 提供前端页面和反向代理，配置 HTTPS，避免视频全量缓冲落盘 |
| 容器部署 | Docker Engine + Docker Compose | `web`、`api` 两个核心容器及持久化数据，支持单机维护 |
| 依赖管理 | npm workspaces + package-lock.json | 统一管理前后端依赖，使用锁文件保证安装结果可重复 |
| 单元与接口验证 | Vitest + Fastify 测试能力 | 重点验证鉴权、Range、上传状态、流量限制和异常处理 |
| 浏览器验证 | Playwright + 真实安卓浏览器 | 自动化界面验证与真实手机上传、播放验证相结合 |

后续可选技术：

| 技术 | 启用条件 |
| --- | --- |
| PWA / Service Worker | 需要添加到桌面时启用，不默认离线缓存视频或授权信息 |

### 9.1 核心数据

| 数据 | 主要字段 |
| --- | --- |
| 用户 | 唯一账户、密码哈希、验证码配置、恢复信息 |
| 登录会话 | 会话 ID、创建/过期时间、撤销状态、必要的设备信息 |
| 分类 | ID、名称、排序、创建时间 |

| 上传任务 | 任务 ID、对象路径、分片状态、文件校验信息、完成状态 |
| 观看记录 | 视频 ID、观看位置、更新时间 |
| 播放会话 | 所属登录会话、视频 ID、活动状态及计量关联 |
| 应用流量记录 | 统计周期、实际发送字节、异常/超限事件 |

数据库保存 OSS 对象路径等元数据，不保存长期签名播放 URL。初始化、重启和模式切换不能丢失已有记录。

### 9.2 服务边界

- 视频列表和元数据接口只返回当前账户有权访问的信息。
- 播放授权接口根据当前模式返回站内播放入口或短期 OSS 地址，不把授权凭证混入通用列表。
- A 的视频流接口负责鉴权、范围读取、数据转发和计量。
- 上传初始化、分片、续传和完成接口均验证任务归属与状态。
- 数据库与 OSS 状态不一致时提供明确的失败状态和人工核查方式，不自动删除任一侧的数据。

| AC-12 | 服务器实测访问杭州 OSS 内网 Endpoint，验证身份和网络限制，并保留正常管理能力 |
| AC-13 | 容器重启和升级后，账户、分类、观看记录和上传状态保留 |
| AC-14 | 镜像、前端产物、示例配置和日志不包含真实长期凭证或敏感会话信息 |
